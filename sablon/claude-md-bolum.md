{{NO}}. Claude Account Switching (Shared Session List)
Goal: The user has more than one Claude account and switches between them in the Claude desktop app only to change usage limits. Switching accounts must change nothing else: the session list, chat history, worktrees and settings must stay the same.

Mechanism: The desktop app keeps the Code tab session list per account under `<data>\claude-code-sessions\<accountUUID>\<orgUUID>\local_*.json`; chat transcripts in `~/.claude/projects` are account-independent. An account can use more than one org folder. The script `{{BETIK_KLASORU}}\hesap-oturum-esitle.ps1` keeps all of these folders as REAL folders and syncs them both ways by copying. The newest version of every `local_*.json` and `deleted_*` file is copied to every other folder, keeping its last-write time so nothing bounces back and forth. A session the user deleted (`deleted_<id>` marker) has its leftover copies moved to `yedek\<time>_silinen`, not deleted. The marker is matched against every id of a record, as the app itself does: `cliSessionId`, `unarchivedCliSessionId`, `priorCliSessionIds` and the file-name id (`local_<id>.json`). The source of a copy is the newest VALID version, meaning it parses as JSON and its `sessionId` equals the file name. A corrupt or half-written version is never copied, and because it is newer it is never overwritten either. It never deletes files. The log moves to `esitleme_<time>.log` when it passes 5 MB. It was installed with `kur.ps1` from the claude-desktop-session-sync repository (https://github.com/realperest/claude-desktop-session-sync) on {{TARIH}}.

Junction Ban: Never use NTFS junctions or symlinks for these folders. Newer app versions refuse to write into them (`Failed to save session ...: Refusing non-directory at private dir path (symlink/file plant)` in `%LOCALAPPDATA%\Claude\logs\main.log`). The app can still read through a junction, so the list looks fine. But new sessions and changes are never saved and are lost at the next account switch or restart; a "Gönderilemedi" send error likely comes from the same failure. The script turns any junction it finds back into a real folder. If sessions go missing, search that log for `Failed to save session` first. The app saves a session's entry only when its metadata changes (title, remote control, etc.), not on every message.

Background Watcher: After each normal run (hook or logon task), the script starts a hidden watcher (`-Izle`). It runs as a single instance through the mutex `Global\ClaudeHesapOturumIzle` and is started through WMI so it outlives the hook. The watcher syncs the folders every 15 seconds (every 2 seconds while the app is closed) and runs the repair and settings sync every 10 minutes. It logs only sync runs that add a new file or move a deleted one; runs that only copy updated entries are not logged. When the script file changes, it restarts itself with the new version. Because of this, the other account's folder is already up to date when the user switches accounts. The active folder is read from the last `Loaded N persisted sessions from <path>` line in the app log. To check it: `Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" | Where-Object CommandLine -match '-Izle'`.

Missing Entry Repair: A session can have a transcript in `~/.claude/projects/<project>/<cliSessionId>.jsonl` but no `local_*.json` entry. This happens when the app moves its data folder while sessions are open, or when it cannot save (see Junction Ban). Such sessions are missing from the sidebar even though the conversation is intact. The script rebuilds the missing entry in the active folder from the transcript, after backing up that folder to `yedek\<time>_onarim_oncesi`, and the sync spreads it to the other folders. For a worktree session, it writes the worktree anchor and reuses the old lessee id from `git-worktrees.json` as the `sessionId` (see Worktree Lease). It skips old CLI ids that the app log maps (`Mapping internal session local_X to CLI session Y`) to a session that still has an entry. It does this only when all of the following hold: the transcript has `"entrypoint":"claude-desktop"`, it is not a subagent transcript, it changed in the last 30 days, it was created more than 15 minutes ago, there is no `deleted_<cliSessionId>` marker and no `<cliSessionId>.desktop-released.json` file (so sessions the user deleted never come back), and its `cwd` folder still exists. The entry title is taken from the transcript's `custom-title`, falling back to the first user message.

Worktree Anchor: A worktree session's entry must have, in `gitAnchors`, an anchor for the worktree itself: `{gitRoot: <worktreePath>, commonDir: <repo>\.git, gitDir: <repo>\.git\worktrees\<name>, trustedAt}`. The `gitdir:` line in `<worktree>\.git` gives `gitDir`. Without this anchor, the app tries to create the worktree again and fails with `this session's branch is checked out somewhere else in this repository`, and every message in that session ends with "Bir şeyler ters gitti". The script writes the anchor when it repairs an entry. It also adds a missing anchor to existing entries while the app is closed (the watcher checks every 2 seconds while the app is closed), or while the app is open with `-ZorlaDuzelt`; the fix takes effect after a full restart from the tray. It does not add `writtenBranches`.

Worktree Lease: The anchor alone is not enough. The app keeps a worktree registry in `<data>\git-worktrees.json` (`worktrees.<name>.leasedBy = <local session id>`). It treats a worktree as a session's own only when `leasedBy` matches that session; otherwise it tries to create the worktree again and fails the same way. `Duzelt-WorktreeKiralari` re-leases a worktree to the session that uses it (by `worktreeName`), but only when the current lessee has no entry in any account folder. It backs up to `yedek\<time>_worktree_defteri_oncesi`, and it runs only while the app is closed, or with `-ZorlaDuzelt`. A repair reuses the registry's old lessee id as the new `sessionId` when that id has no entry. If a session shows "Bir şeyler ters gitti", search `main.log` for `not recreating its worktree` and compare `leasedBy` with the session id. A fix the app holds in memory takes effect only after a real quit from the tray (tray icon, right-click, Quit). Closing the window does not quit the app. Check that the restart really happened with `Get-Process claude | Where-Object Path -match WindowsApps` (start time) and with a new `Loaded N persisted sessions` line in `main.log`.

Shared Account Settings: The script also syncs two plain per-account settings files in the data folder. It backs them up to `yedek\<time>_ayar_oncesi` first and writes atomically. `ccd-session-presets.json`: the `byAccount.<accountUUID>.presets` lists are merged by `id`. `mcp-user-tool-toggles.json`: the `owners.<accountUUID>` lists are merged. It only adds missing items; it never edits or deletes an existing one. Setting values are never written to the log. It runs only while the desktop app is closed: while the app is open, it rewrites these files from memory and drops the addition. It sends no notification.

Sidebar Custom Groups: Custom sidebar groups (manual sections) live in the app's renderer Local Storage (leveldb). That store is binary and locked by the app, so the script does not touch it. A custom group with the same name as a project makes the project look split in two in the sidebar. If the user reports a project shown twice, check `mcp__ccd_sidebar__list_sections` / `list_groups`. If a manual group duplicates a project name, delete it with `mcp__ccd_sidebar__delete_group` after the user approves. Its sessions are not deleted; they fall back to the project grouping.

Data Folder Move Warning: The script records the data folders it last saw in `{{BETIK_KLASORU}}\durum.json`. If they change between runs, it logs an UYARI line and reports that the app moved its data folder.

Automation: A SessionStart hook in `{{CLAUDE_KLASORU}}\settings.json` runs this script at the start of every session; each run also starts the background watcher if it is not running. The app reads the session list before the hook runs, so a repair made by the hook appears only after a full restart. Do not remove or change this hook without the user's approval. A Windows logon scheduled task named `Claude hesap oturum esitleme` runs the script with `-Bildir` (shows a popup only when something changed) before the app starts. The user installs it by running `kur.ps1` or the script with `-GorevKur` in their own terminal. The Claude Code auto-mode classifier blocks Claude from creating this task; do not try to work around that block.

Data Location: The app is an MSIX package. Its data folder is either `%LOCALAPPDATA%\Packages\Claude_<id>\LocalCache\Roaming\Claude` (seen as `%APPDATA%\Claude` inside the app) or `%LOCALAPPDATA%\Claude-Data\claude_<id>`, and the app may move it from the first to the second by itself. Always use the real path, never the virtualized `%APPDATA%` path. Data folder found at install time: `{{VERI_KLASORU}}`. The `_eski*` folders next to the account folders are backups from old versions and are ignored. Sync results are written to `{{BETIK_KLASORU}}\esitleme.log` (line "dosya esitlendi"). The app log is `%LOCALAPPDATA%\Claude\logs\main.log`.

When The Hook Reports A Change, Repair Or Move: If the hook output says sessions were added to the active account's list, entries were rebuilt or the data folder moved, tell the user to fully quit the app from the system tray (tray icon, right-click, Quit; closing the window is not enough) and reopen it so that the list appears. Signing out and signing in to the other account also makes the app re-read the list, so after an account switch no extra restart is needed. Order when switching: let any running reply finish, switch the account, check the list, and only if something is missing quit from the tray and reopen. An account that was never signed in on this computer has no folder yet; after its first sign-in, the watcher fills its folder within seconds, then sign out and in once more so that the app reads the full list.

Troubleshooting: If sessions are missing after an account switch, run `powershell -NoProfile -ExecutionPolicy Bypass -File {{BETIK_KLASORU}}\hesap-oturum-esitle.ps1 -KuruCalisma` first (no changes), then read `{{BETIK_KLASORU}}\esitleme.log`. Backups are in `{{BETIK_KLASORU}}\yedek\`; install-time backups of `settings.json` and `CLAUDE.md` are in `yedek\kurulum_<time>\`, and the install log is `{{BETIK_KLASORU}}\kurulum.log`. This setup works per computer: it does not sync sessions between computers, because transcripts and worktrees live on each computer's own disk. Per-account items that are still NOT shared: sidebar custom groups and pins, claude.ai connectors, claude.ai skills and plugins, cloud sessions, background agent sessions (`local-agent-mode-sessions\<accountUUID>`) and the per-org extension allowlist in `config.json`. Set these up once in each account. Never enter account credentials on the user's behalf. The script's source is the GitHub repository https://github.com/realperest/claude-desktop-session-sync; to update it, pull the repository and run `kur.ps1` again. The desktop app contains a native multi-account feature behind a server feature gate (with the policy `disableMultiAccount`). It is rolled out by Anthropic; do not force it. When it appears in the account menu, re-evaluate whether this script is still needed. A risk-free alternative without switching: keep Desktop on one account and use Claude Code in VS Code/Cursor or the CLI on the other, since their sign-ins are independent and their history is local.
Orange Sidebar Dots: An orange "needs input / blocked" dot means the session's last turn left the user something open: the last next-step box asked a question, or the turn ended without a box. Opening the session does not clear it. "Mark as completed" only hides it, and the app deletes those marks (Local Storage keys `epitaxy-awaiting-ack-v1` and `epitaxy-unread-v1`) at every sign-out, so the dots return after each account switch. This is app behavior; do not edit Local Storage. To prevent it, close every turn with the next-step box (`mcp__ccd_turn__wrap_up`), even a short reply, when a tool was used, when the user answered a box question with typed text, or when the previous box was blocked. If nothing is left to decide, send the recap only. The box state (`turnWrapUp`) is stored in the session record and synced across accounts.
