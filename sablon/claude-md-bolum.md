{{NO}}. Claude Account Switching (Shared Session List)
Goal: The user has more than one Claude account and switches between them in the Claude desktop app only to change usage limits. Switching accounts must change nothing else: the session list, chat history, worktrees and settings must stay the same.

Mechanism: The desktop app keeps the Code tab session list per account under `<data>\claude-code-sessions\<accountUUID>\<orgUUID>\local_*.json`; chat transcripts in `~/.claude/projects` are account-independent. The script `{{BETIK_KLASORU}}\hesap-oturum-esitle.ps1` merges every account folder into one shared folder (copies missing session files, backs up, renames the old folder to `_eski_<time>`, and replaces it with an NTFS junction). It also repairs broken junctions. It never deletes files. It was installed with `kur.ps1` from the CLAUDE_BIRLESTIR repository on {{TARIH}}.

Missing Entry Repair: A session can have a transcript in `~/.claude/projects/<project>/<cliSessionId>.jsonl` but no `local_*.json` entry. This happens when the app moves its data folder while sessions are open. Such sessions are missing from the sidebar even though the conversation is intact. The script rebuilds the missing entry in the shared folder from the transcript, after backing up the folder to `yedek\<time>_onarim_oncesi`. It does this only when all of the following hold: the transcript has `"entrypoint":"claude-desktop"`, it is not a subagent transcript, it changed in the last 30 days, it was created more than 15 minutes ago, there is no `deleted_<cliSessionId>` marker and no `<cliSessionId>.desktop-released.json` file (so sessions the user deleted never come back), and its `cwd` folder still exists. The entry title is taken from the transcript's `custom-title`, falling back to the first user message.

Shared Account Settings: The script also syncs two plain per-account settings files in the data folder. It backs them up to `yedek\<time>_ayar_oncesi` first and writes atomically. `ccd-session-presets.json`: the `byAccount.<accountUUID>.presets` lists are merged by `id`. `mcp-user-tool-toggles.json`: the `owners.<accountUUID>` lists are merged. It only adds missing items; it never edits or deletes an existing one. Setting values are never written to the log.

Sidebar Custom Groups: Custom sidebar groups (manual sections) live in the app's renderer Local Storage (leveldb). That store is binary and locked by the app, so the script does not touch it. A custom group with the same name as a project makes the project look split in two in the sidebar. If the user reports a project shown twice, check `mcp__ccd_sidebar__list_sections` / `list_groups`. If a manual group duplicates a project name, delete it with `mcp__ccd_sidebar__delete_group` after the user approves. Its sessions are not deleted; they fall back to the project grouping.

Data Folder Move Warning: The script records the data folders it last saw in `{{BETIK_KLASORU}}\durum.json`. If they change between runs, it logs an UYARI line and reports that the app moved its data folder.

Automation: A SessionStart hook in `{{CLAUDE_KLASORU}}\settings.json` runs this script at the start of every session. The app reads the session list before the hook runs, so a repair made by the hook appears only after a full restart. Do not remove or change this hook without the user's approval. A Windows logon scheduled task named `Claude hesap oturum esitleme` runs the script with `-Bildir` (shows a popup only when something changed) before the app starts. The user installs it by running `kur.ps1` or the script with `-GorevKur` in their own terminal. The Claude Code auto-mode classifier blocks Claude from creating this task; do not try to work around that block.

Data Location: The app is an MSIX package. Its data folder is either `%LOCALAPPDATA%\Packages\Claude_<id>\LocalCache\Roaming\Claude` (seen as `%APPDATA%\Claude` inside the app) or `%LOCALAPPDATA%\Claude-Data\claude_<id>`, and the app may move it from the first to the second by itself. Junction targets must always use the real path, never the virtualized `%APPDATA%` path. Data folder found at install time: `{{VERI_KLASORU}}`. The current shared folder is written to `{{BETIK_KLASORU}}\esitleme.log` on every run (line "ana klasor").

When The Hook Reports A Merge, Repair Or Move: If the hook output says folders were merged, entries were rebuilt, settings were synced or the data folder moved, tell the user to fully quit the app from the system tray (closing the window is not enough) and reopen it so that the list appears. Signing out and signing in to the other account also makes the app re-read the list, so after an account switch no extra restart is needed. Order when switching: let any running reply finish, switch the account, check the list, and only if something is missing quit from the tray and reopen. An account that was never signed in on this computer has no folder yet; after its first sign-in, sign out and in once more so that the next run can link it.

Troubleshooting: If sessions are missing after an account switch, run `powershell -NoProfile -ExecutionPolicy Bypass -File {{BETIK_KLASORU}}\hesap-oturum-esitle.ps1 -KuruCalisma` first (no changes), then read `{{BETIK_KLASORU}}\esitleme.log`. Backups are in `{{BETIK_KLASORU}}\yedek\`; install-time backups of `settings.json` and `CLAUDE.md` are in `yedek\kurulum_<time>\`, and the install log is `{{BETIK_KLASORU}}\kurulum.log`. This setup works per computer: it does not sync sessions between computers, because transcripts and worktrees live on each computer's own disk. Per-account items that are still NOT shared: sidebar custom groups and pins, claude.ai connectors, claude.ai skills and plugins, cloud sessions, background agent sessions (`local-agent-mode-sessions\<accountUUID>`) and the per-org extension allowlist in `config.json`. Set these up once in each account. Never enter account credentials on the user's behalf.
